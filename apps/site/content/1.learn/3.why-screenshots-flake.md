A visual test that fails without any change to the code teaches people to approve without looking, and from then on the suite is worthless. Flakiness is the thing to design against from day one. Almost all of it comes from a short list of causes, and each has a fix. Switch them on below and watch the diff:

## The environment renders differently

Two machines do not draw the same page the same way. Font hinting and sub-pixel positioning differ between macOS, Linux and Windows; the same browser renders text differently between its own versions; a headless browser with GPU rasterisation produces different anti-aliasing from one with software rasterisation; system fonts differ, so a page that falls back to "the default sans-serif" looks different everywhere.

The fix is to render in one pinned environment and nowhere else: a Docker image with a specific browser version and bundled fonts, used both for recording baselines and for comparing. Playwright publishes [versioned images](https://playwright.dev/docs/docker), Cypress has [its own](https://github.com/cypress-io/cypress-docker-images), and several tools (pixsame's pinned renderer, Loki's docker target, the hosted services' render farms) make it the default. Developers on laptops then either run the comparison inside that container or update baselines only from CI. Baselines made on a Mac and compared on Linux are the single most common source of noise.

If a pinned renderer is not an option, record the OS and browser in the baseline's name or metadata (Playwright and Vitest append `-chromium-linux` to the file name; the [manifest](/manifest) keeps `platform` and `renderer` per entry) and keep one baseline per combination you actually test in.

## Fonts

Web fonts load asynchronously. A screenshot taken before the font arrives shows the fallback. Wait for `document.fonts.ready` before capturing, self-host the fonts so there is no network variance, and prefer `font-display: block` in test builds so a late font never swaps in halfway. Icon fonts are worse than text fonts: use SVG icons.

## Animations and transitions

A CSS transition caught mid-way is a different image every time. Disable animations globally for screenshots: Playwright's `animations: 'disabled'` option finishes CSS animations and transitions before capturing, most other tools accept an injected stylesheet (`*, *::before, *::after { animation: none !important; transition: none !important; }`), and emulating `prefers-reduced-motion: reduce` turns off well-behaved animations at the source. Carousels, auto-playing video, typewriter effects and skeleton shimmer need to be stopped explicitly.

## Timing and asynchronous content

Capture after the page is idle, not after it has loaded: images decoded, lazy-loaded sections in view, data fetched, spinners gone. Waiting a fixed number of milliseconds is the flaky way to do this; waiting for a specific element or network idle is the stable way. Mock the data so the same content comes back every run.

## Dynamic content

Dates, times, counters, random avatars, ads, maps, charts with live data, cursors blinking in inputs. Each needs one of: mock the source, freeze the clock, mask the region, or hide the element with a test-only stylesheet. Tools offer `mask` (Playwright), ignore regions (odiff, Applitools) or a `hideSelectors` list (BackstopJS) for exactly this; the stylesheet injection works everywhere.

## Viewport, scrollbars and device pixel ratio

A screenshot of a 1280-wide viewport on a machine whose window is 1200 wide is a different screenshot. Set the viewport explicitly. Scrollbars take space on Linux and Windows and overlay on macOS, which shifts layout by the scrollbar width; hide them for screenshots. A device pixel ratio of 2 doubles every dimension and changes anti-aliasing; fix it to 1 (or to 2, but fix it).

## Partial renders and hover state

The mouse resting over a button in a headless browser produces a hover state nobody intended. Move the pointer away before capturing. A focused input shows a caret that blinks; blur it or hide the caret with CSS.

## The order to try things

1. Pin the renderer (Docker image, exact browser version, bundled fonts). This removes the majority.
2. Disable animations and wait for idle.
3. Mock data and freeze time.
4. Mask what is left.
5. Only then raise the threshold, and only for the screenshot that needs it.

Raising the threshold first is tempting and wrong: it hides real regressions in the same proportion as it hides noise.
