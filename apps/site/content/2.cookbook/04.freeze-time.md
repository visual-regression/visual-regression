## Symptom

A date, a "3 minutes ago", a countdown or a calendar highlights in the diff while everything around it is identical. The baseline was recorded on a Tuesday; today is Wednesday. A variation: a run on a developer's laptop and a run in CI disagree on the hour because the machines sit in different timezones, or the baseline shows `2/3/2026` and the actual `03/02/2026` because the locale differs.

## Fix

Freeze the clock the page reads from, freeze the one the server reads from, and pin the timezone and locale of the browser.

::tabs{sync="runner"}
  :::tabs-item{label="Playwright"}
  `page.clock.setFixedTime` is the recommended way to pin the date; call it before the page loads so the first render already sees the fixed time:

  ```ts
  await page.clock.setFixedTime(new Date('2026-03-02T10:00:00Z'));
  await page.goto('/dashboard');
  await expect(page).toHaveScreenshot();
  ```

  `setFixedTime` leaves timers running, so animations and polling still work. If the page needs timers under control too (a countdown that must be stopped), install the full clock and pause it:

  ```ts
  await page.clock.install({ time: new Date('2026-03-02T10:00:00Z') });
  await page.goto('/checkout');
  await page.clock.pauseAt(new Date('2026-03-02T10:00:00Z'));
  ```

  Timezone and locale are context options:

  ```ts [playwright.config.ts]
  use: { timezoneId: 'Europe/Warsaw', locale: 'en-US' },
  ```
  :::

  :::tabs-item{label="Cypress"}
  `cy.clock` before `cy.visit` gives the page a fake `Date`; pass `['Date']` to leave timers alone:

  ```ts
  cy.clock(Date.UTC(2026, 2, 2, 10), ['Date']);
  cy.visit('/dashboard');
  cy.matchImage();
  ```

  Without the second argument, `cy.clock` also freezes `setTimeout`, `setInterval` and `requestAnimationFrame`; use `cy.tick(ms)` to advance them. Each new page gets a fresh clock that starts at the same `now`.

  Cypress has no timezone or locale option. The browser inherits the timezone of the process that launched it, so set it in the environment of the command (`TZ=Etc/UTC npx cypress run` on Linux and macOS runners) and make it the same in CI and locally.
  :::

  :::tabs-item{label="Vitest"}
  In browser mode the fake timers run inside the browser, so the component sees them:

  ```ts
  beforeEach(() => {
    vi.useFakeTimers({ toFake: ['Date'] });
    vi.setSystemTime(new Date('2026-03-02T10:00:00Z'));
  });
  afterEach(() => vi.useRealTimers());
  ```

  `vi.setSystemTime` on its own (without fake timers) only mocks `Date` and `Temporal.Now`, which is usually what a screenshot needs. Timezone and locale go to the Playwright provider's context:

  ```ts [vitest.config.ts]
  provider: playwright({ contextOptions: { timezoneId: 'Europe/Warsaw', locale: 'en-US' } }),
  ```
  :::

  :::tabs-item{label="Any tool"}
  Tools without a clock API still control the page before it runs scripts. Give the app a seam: when a test flag is set, it reads "now" from a query parameter or a global instead of `Date.now()`.

  ```ts [app/clock.ts]
  const fixed = new URLSearchParams(location.search).get('now');
  export const now = () => (fixed ? new Date(fixed) : new Date());
  ```

  BackstopJS scenarios then point at `/dashboard?now=2026-03-02T10:00:00Z`. With the Playwright engine, the `onBefore` script can also call `page.clock.setFixedTime(...)` if the installed Playwright has `page.clock`. For Storybook, a decorator that installs a fake clock (`@sinonjs/fake-timers`) around the story does the same for every tool that screenshots stories.
  :::
::

### Server-side time

A server-rendered page bakes dates into the HTML before the browser's clock matters. Freeze the server too: run it with a fixed `TZ` (`TZ=Etc/UTC node server.js`), and give it the same seam, a `now()` function that a test environment variable can pin. If the data comes from an API, [mock it](/cookbook/deterministic-data); mocked payloads carry fixed timestamps.

### Timezones and locales

A fixed instant is still formatted by the browser. `10:00Z` is `11:00` in Warsaw and `05:00` in New York; `toLocaleDateString()` puts the month first in `en-US` and the day first in `en-GB`. Pin both the timezone and the locale, and record them in the baseline's name or metadata when you test more than one (the [manifest](/manifest) has `platform` and `renderer` for this; a `locale` suffix in the screenshot name is the simple option).

## Verify

Set the fixed time to a date in a different year than today and to a different timezone than your machine's. If the screenshot still matches the baseline, every date on the page comes from the frozen clock. Then run the test with `TZ` changed in the shell (`TZ=Pacific/Kiritimati npx playwright test`): with `timezoneId` set it must still pass; without it you have found the next thing to pin.
