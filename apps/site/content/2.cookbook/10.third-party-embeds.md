## Symptom

A map tile loads a different frame of satellite imagery. An ad slot shows another ad, or no ad, or a "loading" box. A YouTube embed has a different thumbnail, a chat widget pops a greeting after a random delay, an iframe from a partner renders their latest release. Each is a region you do not control, with a network dependency on a service that may be slow, rate-limited or offline in CI.

## Fix

Three options, from best to acceptable: do not load the embed in tests, load a placeholder of the same size, or mask it. All three should keep the layout identical to production so the surrounding page is still tested.

### Block the requests

::tabs{sync="runner"}
  :::tabs-item{label="Playwright"}
  Abort the hosts you never want in a test, on the context so popups and new pages are covered too:

  ```ts [fixtures.ts]
  const BLOCKED = /maps\.googleapis\.com|doubleclick\.net|intercom\.io|youtube\.com/;

  export const test = base.extend({
    context: async ({ context }, use) => {
      await context.route(BLOCKED, (route) => route.abort());
      await use(context);
    },
  });
  ```

  For an iframe that must exist (the layout reserves space for it), fulfill it with an empty document instead of aborting:

  ```ts
  await page.route('**/embed/**', (route) =>
    route.fulfill({ contentType: 'text/html', body: '<!doctype html><body style="background:#eee">' }),
  );
  ```
  :::

  :::tabs-item{label="Cypress"}
  `blockHosts` blocks at the proxy and answers every request to those hosts with a 503:

  ```ts [cypress.config.ts]
  export default defineConfig({
    blockHosts: ['*.doubleclick.net', 'maps.googleapis.com', '*.intercom.io'],
  });
  ```

  Hosts only, no protocol, and `*` wildcards. For an embed that must render something, stub it with `cy.intercept` before the visit:

  ```ts
  cy.intercept('https://www.youtube.com/embed/**', { statusCode: 204, body: '' });
  cy.visit('/article');
  cy.matchImage({ screenshotConfig: { blackout: ['iframe.youtube'] } });
  ```
  :::

  :::tabs-item{label="Vitest"}
  A component test should not reach a third-party service at all. Inject the embed as a dependency and pass a placeholder in tests:

  ```tsx
  render(<Article map={<div data-testid="map" style={{ height: 320 }} />} />);
  await expect.element(page.getByTestId('article')).toMatchScreenshot();
  ```

  Where the component loads a script itself, mock the module (`vi.mock('@googlemaps/js-api-loader', ...)`) so the loader resolves to a stub that draws nothing.
  :::

  :::tabs-item{label="Any tool"}
  Put the switch in the app: when a test flag is set, render a placeholder instead of the embed, with the same dimensions.

  ```tsx
  const SCREENSHOT = import.meta.env.VITE_SCREENSHOT_MODE === 'true';

  export function Map(props) {
    if (SCREENSHOT) return <div className="map map--placeholder" aria-hidden="true" />;
    return <GoogleMap {...props} />;
  }
  ```

  Tools that only have a URL (BackstopJS, Lost Pixel, the hosted services) then screenshot the placeholder. BackstopJS can also remove the element with `removeSelectors` or hide it with `hideSelectors`, and Chromatic, Percy and Applitools all have region-ignore features for the same purpose.
  :::
::

### Per embed

- **Maps**: a placeholder with the map's height and a neutral background. If the map must render, use a static map image with a fixed center and zoom, served from your own origin.
- **Ads**: never load them in tests. Keep the slot's reserved size (which also tests your layout-shift behavior).
- **Video**: a poster image and `preload="none"`; block the player's script. The player chrome (controls, progress bar) is a third-party UI that updates on its own schedule.
- **Chat widgets and consent banners**: do not initialize them under the test flag, or block their hosts; they open on timers and shift everything. If the banner is part of the product, screenshot it in its own test with the timer frozen.
- **Partner iframes**: fulfill with a same-size empty document; an iframe you do not control cannot be stabilized from the outside.

### When masking is enough

If the embed is a fixed-size box and the test is about the page around it, [mask it](/cookbook/mask-dynamic-regions) and move on. Blocking is still better: a blocked request also removes a network wait and a source of CI timeouts.

## Verify

Run the test with no network access to anything but your app (Playwright: a context `route('**/*')` that aborts every request not pointing at your origin). It must pass. Then run it ten times online: the result must not depend on the third party's response time.
