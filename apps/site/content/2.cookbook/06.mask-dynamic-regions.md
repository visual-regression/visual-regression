## Symptom

One region of the page differs on every run and you already know why: a live clock, a visitor counter, an ad slot, an avatar from an external service, a "last updated" line. The rest of the page is identical. You cannot (or do not want to) change what renders there, so you want the comparison to look away.

## Fix

Every tool has a way to exclude a region. Prefer the one that keeps the layout intact (a box painted over the element, or `visibility: hidden`) over one that removes the element, so the rest of the page stays where it is.

::tabs{sync="runner"}
  :::tabs-item{label="Playwright"}
  `mask` paints a box over each matching element before the capture; `maskColor` picks the color (default `#FF00FF`, pink so it is obviously a mask):

  ```ts
  await expect(page).toHaveScreenshot({
    mask: [page.getByTestId('clock'), page.locator('.ad-slot')],
    maskColor: '#00ff00',
  });
  ```

  A stylesheet via `stylePath` can hide elements for every screenshot of the suite instead:

  ```css [tests/screenshot.css]
  [data-testid='clock'],
  .ad-slot {
    visibility: hidden !important;
  }
  ```
  :::

  :::tabs-item{label="Cypress"}
  `blackout` is Cypress's own screenshot option, passed through `screenshotConfig`; the elements are covered with a black box:

  ```ts
  cy.matchImage({
    screenshotConfig: { blackout: ['[data-testid=clock]', '.ad-slot'] },
  });
  ```

  `blackout` does not apply to `capture: 'runner'` screenshots. For a suite-wide rule, overwrite the command in the support file so every `matchImage` call carries the same list, or inject a stylesheet with `visibility: hidden` before the capture.
  :::

  :::tabs-item{label="Vitest"}
  With the Playwright provider, `screenshotOptions` accepts Playwright's screenshot options, including `mask` with Vitest locators:

  ```ts
  await expect.element(page.getByTestId('card')).toMatchScreenshot({
    screenshotOptions: { mask: [page.getByTestId('clock')] },
  });
  ```
  :::

  :::tabs-item{label="Any tool"}
  BackstopJS has two scenario lists, with different effects on layout:

  ```json [backstop.json]
  {
    "hideSelectors": ["[data-testid=clock]"],
    "removeSelectors": [".ad-slot"]
  }
  ```

  `hideSelectors` sets `visibility: hidden` (the element keeps its box), `removeSelectors` sets `display: none` (the content below moves up). Prefer the first unless the element's size is itself unstable.

  For any other tool, a test-only stylesheet does the same thing. Ship it in the test build or inject it from the tool's hook:

  ```css
  .screenshot-mode [data-testid='clock'] {
    visibility: hidden !important;
  }
  ```
  :::
::

### Mask or mock?

A mask hides pixels, not behavior. It is the right tool when the region's *content* is noise and its *size* is stable: a timestamp of fixed width, an ad slot with fixed dimensions, an avatar in a fixed circle. It is the wrong tool when:

- the element's size changes with its content ("3 new messages" vs "12 new messages"), because the layout around it shifts and the mask does not cover the shift. [Mock the data](/cookbook/deterministic-data) or [freeze the time](/cookbook/freeze-time) instead.
- the element is what the test is about. A masked component cannot regress.
- the list of masks grows with every flake. Two or three masks per page is maintenance; twenty is a sign that the data should be mocked.

A mask also hides real regressions inside the region (a broken date format stays broken). Tests that care about the format belong in a unit test of the formatter.

### Mask consistently

Record the baseline with the mask on. A baseline captured without the mask and compared with it fails on the mask itself. Keep the mask list in one place (a config default, a custom command, a shared stylesheet) so every screenshot of the page uses the same one, and so the reviewer sees the same pink boxes in every image.

## Verify

Run the test ten times (`--repeat-each 10`, `Cypress._.times`, `{ repeats: 10 }`). Then change the content of the masked element (a different fixture, a different fixed time) and run again: the test must still pass. Finally, break something next to the mask on purpose; the test must fail, which proves the mask is not bigger than it should be.
