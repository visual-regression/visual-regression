## Symptom

Every line of text is highlighted, but the layout is the same. Or the diff is one word in a fallback font while the rest of the page is fine. Both mean the screenshot was taken while a web font was still loading, or the font never arrived and the system fallback rendered instead. On a slow CI network the same page flakes in different places each run.

## Fix

Three parts: wait for the fonts, make sure they always load the same way, and avoid fonts for things that are not text.

### Wait for `document.fonts.ready`

The promise resolves once the document has finished loading fonts and the layout that depends on them is done.

::tabs{sync="runner"}
  :::tabs-item{label="Playwright"}
  ```ts
  await page.goto('/');
  await page.evaluate(() => document.fonts.ready);
  await expect(page).toHaveScreenshot();
  ```

  If a page can trigger more font loads after an interaction (a modal with a different weight), evaluate again right before the capture.
  :::

  :::tabs-item{label="Cypress"}
  `.then` waits for a returned promise, so:

  ```ts
  cy.visit('/');
  cy.document().then((doc) => doc.fonts.ready);
  cy.matchImage();
  ```

  Put it in a custom command if every screenshot needs it, or overwrite `matchImage` in the support file so it always runs first.
  :::

  :::tabs-item{label="Vitest"}
  ```ts
  render(<Pricing />);
  await document.fonts.ready;
  await expect.element(page.getByTestId('pricing')).toMatchScreenshot();
  ```
  :::

  :::tabs-item{label="Any tool"}
  BackstopJS: in the `onReady` engine script, `await page.evaluate(() => document.fonts.ready)`. Tools without a hook can wait for a marker the app sets:

  ```js
  document.fonts.ready.then(() => document.documentElement.setAttribute('data-fonts', 'ready'));
  ```

  and use `html[data-fonts="ready"]` as the ready selector (`readySelector` in BackstopJS).
  :::
::

### Self-host the fonts

A font fetched from a third-party CDN is a network dependency in every run: a slow response shows the fallback, an updated file changes the glyphs. Copy the files into the repository, declare them with `@font-face`, and serve them from the app's origin. Pin the version in the file name (`inter-4.0.woff2`) so an update is a visible change in git.

```css
@font-face {
  font-family: 'Inter';
  src: url('/fonts/inter-4.0.woff2') format('woff2');
  font-weight: 100 900;
  font-display: block;
}
```

`font-display: block` gives the font a short block period and an infinite swap period: the text is invisible until the font is in, and never renders in the fallback first. In production you may prefer `swap`; a test build can set `block` so a late font never swaps halfway through a capture. Combined with the wait above, there is nothing left to swap.

### Icon fonts

An icon font has every problem of a text font plus one: when it is missing, the fallback is a box or a wrong glyph, which is a large diff. Inline SVG icons (or an SVG sprite) are loaded with the document and render identically everywhere. If you cannot replace the icon font, at least self-host it and wait for it like any other.

### Fonts that differ per operating system

The fallback stack (`sans-serif`, `system-ui`) resolves to a different font on every OS, and even the same font file is hinted differently by macOS, Windows and Linux. The real fix is to render in one pinned environment ([pin the renderer](/cookbook/pin-the-renderer)). If that is not possible, pixsame's `deterministicRendering` preset launches Chromium with `--font-render-hinting=none --disable-font-subpixel-positioning --disable-lcd-text`, which removes the part of the noise that lives inside the browser; Playwright and Vitest users can pass the same switches through `launchOptions.args`. Different font *files* per OS still need a per-OS baseline.

## Verify

Throttle the network and run the test several times; the result must not depend on when the font arrives:

```ts
// Playwright: delay every font request by two seconds
await page.route('**/*.woff2', async (route) => {
  await new Promise((r) => setTimeout(r, 2000));
  await route.continue();
});
```

Then `--repeat-each 5`. Also run once with the font request aborted (`route.abort()`): the test must fail loudly with a missing-font diff, not pass by accident.
