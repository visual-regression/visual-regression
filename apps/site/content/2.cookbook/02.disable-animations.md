## Symptom

The diff highlights an element in two slightly different positions or opacities, a fade caught halfway, a drawer a few pixels short of open, a button whose hover transition had not finished. Re-running the test produces a different diff each time, in the same place. The [learn chapter](/learn/why-screenshots-flake#animations-and-transitions) explains why; this recipe makes it stop.

## Fix

Three layers, from cheapest to most thorough: let the screenshot tool finish animations, tell the page you prefer reduced motion, and inject a stylesheet that removes what is left. JavaScript-driven motion (carousels, video, typewriter effects) needs a fourth, explicit stop.

::tabs{sync="runner"}
  :::tabs-item{label="Playwright"}
  `toHaveScreenshot` already defaults to `animations: 'disabled'`: finite CSS animations and transitions are fast-forwarded to their end state, infinite ones are canceled and restarted after the capture. Keep it on, and add reduced-motion emulation so animation libraries that honor the media query stop at the source:

  ```ts [playwright.config.ts]
  export default defineConfig({
    use: { reducedMotion: 'reduce' },
    expect: { toHaveScreenshot: { animations: 'disabled' } },
  });
  ```

  For the rest, a test-only stylesheet applied to every screenshot:

  ```ts [playwright.config.ts]
  expect: { toHaveScreenshot: { stylePath: './tests/screenshot.css' } },
  ```

  Note that `page.screenshot()` defaults to `animations: 'allow'`; the assertion is the one with the safe default.
  :::

  :::tabs-item{label="Cypress"}
  `cy.screenshot` pauses JavaScript timers and CSS animations for the capture by default (`disableTimersAndAnimations: true`). With `@pixsame/cypress-plugin-visual-regression-diff`, the `deterministicRendering` preset also injects a stylesheet for the duration of the screenshot that disables transitions, animations and smooth scrolling (and hides the caret and scrollbars):

  ```ts [cypress.config.ts]
  export default defineConfig({
    expose: { pluginVisualRegressionDeterministicRendering: true },
  });
  ```

  Or per screenshot:

  ```ts
  cy.matchImage({ deterministicRendering: true });
  ```

  Set `deterministicRendering: false` on the one screenshot where the end state of an animation is the thing under test. Cypress has no reduced-motion option; the stylesheet below covers what the preset does not.
  :::

  :::tabs-item{label="Vitest"}
  With the Playwright provider, `toMatchScreenshot` sets `animations: 'disabled'` by default. Reduced motion is a context option of the provider, and the stylesheet goes into a setup file:

  ```ts [vitest.config.ts]
  import { playwright } from '@vitest/browser-playwright';

  export default defineConfig({
    test: {
      browser: {
        enabled: true,
        provider: playwright({ contextOptions: { reducedMotion: 'reduce' } }),
        instances: [{ browser: 'chromium' }],
      },
      setupFiles: ['./tests/screenshot-setup.ts'],
    },
  });
  ```

  ```ts [tests/screenshot-setup.ts]
  const style = document.createElement('style');
  style.textContent = `*, *::before, *::after {
    animation-duration: 0s !important; animation-delay: 0s !important;
    transition-duration: 0s !important; transition-delay: 0s !important;
  }`;
  document.head.append(style);
  ```
  :::

  :::tabs-item{label="Any tool"}
  The stylesheet works with every tool that can inject CSS or serve a test build:

  ```css [screenshot.css]
  *,
  *::before,
  *::after {
    animation-duration: 0s !important;
    animation-delay: 0s !important;
    transition-duration: 0s !important;
    transition-delay: 0s !important;
    scroll-behavior: auto !important;
  }
  ```

  Zero durations jump to the end state, which keeps `animation-fill-mode: forwards` results on screen. `animation: none !important` removes the animation and its end state instead; use it when the page should look like it did before anything animated.

  BackstopJS applies it from an engine script, Storybook's test runner from `preVisit`, and Chromatic pauses CSS animations at their end by default (`pauseAnimationAtEnd`) and exposes `prefersReducedMotion: 'reduce'` as a story parameter:

  ```js [backstop_data/engine_scripts/playwright/onReady.js]
  module.exports = async (page, scenario) => {
    await page.addStyleTag({ path: 'tests/screenshot.css' });
  };
  ```

  If you ship a test build, put the same rules behind a `prefers-reduced-motion` media query in the app and emulate the query in the test; the app then stops its own motion and nothing is injected.
  :::
::

### Things the stylesheet does not stop

- **Carousels and auto-advancing sliders** run on timers. Give the component a prop or a global (`window.__SCREENSHOT__`, a query parameter, an environment flag in the test build) that disables autoplay, and set it before the page loads.
- **Video and GIFs** keep moving. Pause the video and show its poster, or replace the element in the test build. `preload="none"` plus a poster image is a stable first frame.
- **Skeleton shimmer** is a CSS animation, so the stylesheet freezes it, but a frozen skeleton is still not the content. Wait for the real content instead ([wait for idle](/cookbook/wait-for-idle)).
- **Canvas and WebGL animations** draw on their own clock; see [canvas, charts and WebGL](/cookbook/canvas-charts-webgl).

## Verify

Run the screenshot test repeatedly on the same build and require every run to pass:

```sh
npx playwright test home.spec.ts --repeat-each 10
```

Cypress has no repeat flag; wrap the test in `Cypress._.times(10, () => it(...))` for the check, then remove it. In Vitest, `test('home', { repeats: 10 }, ...)` does the same.
