## Symptom

A single button is highlighted in the diff, in its hover color, because the pointer happened to rest on it after the last click. Or a thin vertical line inside an input field appears in half of the runs: the caret, blinking, caught on or off. Or a focus ring around the element the test clicked last.

## Fix

Three states, three fixes: move the pointer, hide the caret, blur the element.

::tabs{sync="runner"}
  :::tabs-item{label="Playwright"}
  `toHaveScreenshot` hides the caret by default (`caret: 'hide'`); keep it. For the pointer and the focus, do it explicitly before the capture:

  ```ts
  await page.getByRole('button', { name: 'Add to cart' }).click();
  await page.mouse.move(0, 0); // park the pointer in a corner
  await page.getByRole('button', { name: 'Add to cart' }).blur();
  await expect(page).toHaveScreenshot();
  ```

  If the pointer must rest somewhere neutral on every screenshot, add the two lines to a fixture that wraps `toHaveScreenshot`. When the hover state *is* the subject, hover deliberately (`locator.hover()`) and name the baseline after it (`button-hover.png`).
  :::

  :::tabs-item{label="Cypress"}
  Cypress simulates events, so a resting pointer rarely triggers `:hover` on its own; the caret and the focus ring are the usual culprits. Blur the element and hide the caret with the plugin's injected CSS:

  ```ts
  cy.get('input[name=email]').type('ada@example.com').blur();
  cy.matchImage({ deterministicRendering: true });
  ```

  `deterministicRendering` injects, for the duration of the screenshot, a stylesheet that hides the text caret (and disables animations and scrollbars). Enable it globally with `pluginVisualRegressionDeterministicRendering: true` in `expose` (or `env` on Cypress before 15.10) so every screenshot gets it.
  :::

  :::tabs-item{label="Vitest"}
  `screenshotOptions` takes Playwright's `caret` option; the pointer is moved with `userEvent`:

  ```ts
  await userEvent.click(page.getByRole('button', { name: 'Save' }));
  await userEvent.unhover(page.getByRole('button', { name: 'Save' }));
  page.getByRole('button', { name: 'Save' }).element().blur();
  await expect.element(page.getByTestId('form')).toMatchScreenshot({
    screenshotOptions: { caret: 'hide' },
  });
  ```
  :::

  :::tabs-item{label="Any tool"}
  A stylesheet handles the caret and the focus ring for tools without options:

  ```css [screenshot.css]
  * {
    caret-color: transparent !important;
  }
  :focus,
  :focus-visible {
    outline: none !important;
    box-shadow: none !important;
  }
  ```

  Only hide focus styles when the screenshot is not about keyboard accessibility; a dedicated focus-state screenshot (one per component, with focus applied on purpose) is worth keeping. BackstopJS applies hover on purpose with `hoverSelector` and `postInteractionWait`, so a scenario without it never hovers; to blur, add `document.activeElement.blur()` to the `onReady` script.
  :::
::

### Hover states you want

A hover, focus or active state is worth its own baseline when the design defines it. Capture each on purpose, in its own test, with the interaction applied right before the capture, and name the screenshot after the state. The flake comes from *accidental* interaction state, not from testing it.

## Verify

Run the test ten times; the caret flake in particular shows up as roughly half the runs failing, so ten runs catch it. Then run the suite in a different order (`--shuffle` where available, or a single test in isolation) to make sure no screenshot depends on where the previous test left the pointer.
