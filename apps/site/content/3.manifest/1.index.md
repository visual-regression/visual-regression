Every visual regression tool ends a run the same way: some comparisons passed, some failed, some had no baseline yet, and the images are somewhere on disk. What happens next, a comment on the pull request, a review screen, a button that approves a baseline, needs that information in a form a program can read. Today almost every tool leaves image folders and nothing else, and every review tool parses logs or walks directories to work out what happened.

The visual regression manifest is that missing file: `visual-regression-manifest.json`, one per run, listing every comparison with its status, diff ratio, threshold and the paths of the baseline, actual and diff images, plus where the run happened (CI provider, repository, commit, pull request) and what ran it.

## Built upon CTRF

[CTRF](https://ctrf.io), the Common Test Report Format, is the one cross-tool test results format with a growing ecosystem of reporters and CI integrations. It has no notion of a screenshot comparison: no baseline, actual and diff triple, no diff ratio, no "needs a baseline" outcome. Rather than invent a parallel vocabulary, the manifest uses CTRF's names wherever CTRF has a field (`reportFormat`, `specVersion`, `tool`, `summary`, `commit`, `buildId`, `osPlatform`, `extra`, attachments) and adds only what a visual comparison needs.

The result is a file that converts to a CTRF report and back without renaming anything: `toCtrf` writes one CTRF test of `type: "visual"` per comparison with the images as attachments, so every CTRF-aware PR summary or dashboard shows your visual results today, and `fromCtrf` reads it back. A proposal to document the visual fields upstream is open with the CTRF maintainers.

## Implementations

The manifest is not a standard. It is an open format with one maintainer, a schema, a reference library and converters, and this table is the current state of adoption. It becomes a standard the day a second tool writes or reads it without asking.

| Writes it natively | Converted by `visual-regression-manifest` | Reads it |
| --- | --- | --- |
| [pixsame](https://pixsame.com) Cypress plugin | Playwright `toHaveScreenshot`, Vitest `toMatchScreenshot`, jest-image-snapshot, cypress-image-snapshot, cypress-visual-regression, BackstopJS, Roborazzi, any tool that leaves baseline/actual/diff images | the [viewer](/viewer), the pixsame GitHub App (in preparation), anything that reads CTRF via `toCtrf` |

Adding your tool to the middle column is one file and one test in the [repository](https://github.com/Visual-Regression/visual-regression); adding it to the first is `ManifestWriter` and a few lines in your plugin.

## Install

```bash
npm install visual-regression-manifest
```

The package has no runtime dependencies and ships the JSON Schema, TypeScript types, a reader with validation, a writer that keeps the file complete even when the run is killed, a merger for runs split across machines, and the converters.
